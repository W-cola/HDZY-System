## 环境隔离先于测试

- 业务集成测试会创建账号、客户、合同、发票、回款并触发锁定与删除；只能指向独立测试服务及数据库。
- API_BASE_URL 默认是 http://127.0.0.1:5320/api。运行前确认该服务不是正在使用的业务库，不能因地址是 localhost 就认为可任意写入。
- PGlite 测试使用独立项目副本的 data/pg，不与开发服务共用目录；PostgreSQL 使用独立测试数据库。
- 不在生产执行 seed-demo、restore-demo-data 或现有 core-flow 测试。测试完检查清理结果；目前 afterAll 清理有缺陷。

## 当前命令及限制

```bash
node scripts/verify-workspace-links.mjs
pnpm --filter @vben/web-antd run typecheck
pnpm --filter @vben/web-antd run build
pnpm --filter @vben/server run build
```

typecheck 依赖 wait-runtime.sh；不是脱离平台运行标记的纯命令。后端 package.json 没有独立 typecheck，根 check:type 不能直接等同“前后端都严格类型检查通过”；Nitro build 也不能替代完整类型审查。

现有根脚本：

```bash
pnpm test:unit
pnpm test:integration
```

先修 R11 再把它们作为可信门槛。当前 vitest.config.ts 没排除 vendor-vben 或 integration；test:unit 可能运行重复测试与访问 API 的测试。临时验证某个修复时，在已装好依赖的隔离环境指定具体测试文件，不用默认全目录扫描代替分层设计。

test:e2e 只是 Turbo 脚本入口，不代表已经有可运行的业务端到端套件。

## 权限验收矩阵

| 场景 | 检查方式 | 预期 |
|---|---|---|
| 未登录 | 直接调用业务 API | 明确未授权，无数据返回或写入 |
| 登录但没有页面权限 | 路由访问及直接接口调用 | 菜单不被前端补回；接口独立拒绝 |
| 仅新增 | 创建后尝试提交已有 id | 可新增，不能利用 UPSERT 编辑 |
| 仅编辑 | 保存本人可编辑资源 | 不要求 create；无法改越界资源 |
| self | A 查询/修改 B 的记录 | 拒绝或不可见；附件同样校验 |
| department | 本部门、子部门、兄弟部门各准备记录 | 与决策的部门范围一致 |
| allRead | 直接请求新增、编辑、删除、上传 | 按最终规则拒绝写操作 |
| 多角色 | 一读一写、一窄一宽组合 | 与 D02 约定一致，而非偶然分支放行 |
| 禁用角色/菜单/账号 | 使用旧 token 重试 | 按约定失效，重启不恢复授权 |
| admin / super | 对相同样本验证 | 与 D01 的特权定义一致 |

R01 必须以普通角色回归，不能只测管理员。

## 业务主线

1. 客户创建、重复名称、导入、归属筛选、软删除和恢复；导入故障检查是否部分写入。
2. 联系人和主联系人、跟进与商机关联、商机阶段变更与历史一致。
3. 客户移交及撤回：客户、明细、商机一起成功或一起失败；验证两个管理员并发、无权移交、目标用户停用。
4. 合同草稿与正式提交、比例总和、无效客户/负责人、金额边界、编辑后重新查询、附件上传读取删除。
5. 开票资料换版、合同快照、发票状态和回款确认：按独立维度核对开票总额与已确认回款，不相加充当合同额。
6. 员工档案新增/编辑/删除、重复员工号、身份证/银行卡/劳动合同附件；验证自定义人事角色是否与内置 hr 一致。
7. 权限/组织更改后重启，确认设置未被初始化覆盖；销售统计符合可见范围。

对每个接口同时检查 HTTP 状态、业务 code 和重新查询到的数据。不要用 `返回字段 || 预设正确值` 构造通过断言。

## 测试修复要求

- 将单元测试、集成测试和备份目录明确隔离。
- core-flow 的合同创建只返回 id，应重新查询真实金额；删除 `amount || 1000` 兜底。
- 用户/客户/合同/发票/回款 ID 分开保存，按依赖关系清理，检查业务响应；失败用例也应可回收测试数据。
- 金额口径按 DECISIONS.md 确认后写真实断言。前端可见性与服务端授权分别测试。
- 每轮变更只跑相关验证和必要回归，稳定通过后不无目的扩大测试范围。
